Plugins and the data they touch

PluginWhat it doesData it reads or writes (local unless noted)
ellmos-lock-master
source		 Hooks deny edits and git push on paths that another agent has locked or claimed; commands to set and release locks; an MCP team board for agents on the same computer. Reads LOCK*.txt files in the target folder, its parents and a worktree's main clone; runs git to resolve worktrees. Writes lock files only when you run /lock or /unlock, and a team-lock message when you run /message. The bundled lock-board MCP server (five tools: read, post, claim, release, presence) writes to this computer's team-lock file only when the model calls it; the board holds agent names, file paths and messages. Per session the hook keeps a small JSON file in the system temp folder (ellmos-lock-master) with the session name and the fence numbers of the locks it relied on; it is removed at session end, together with the session's board claims, and pruned after a week. Optional leases (off unless you set ELLMOS_LOCK_LEASES): each edit sends the file's lease key (repository origin and path), host name, session id and tool name to the lease database you configure (a local SQLite file or your own Postgres server); nothing goes to ellmos-ai.
workflowhooker
source		 Closing gate with one rework round, drift and scope warnings, configured per project. Reads the hook input, workflowhooker.toml, project files and git status. Stores per-session counters and hashes and, with ownership = "session" (the starter default), the relative paths of files that were uncommitted at session start plus a content hash each, in ~/.workflowhooker/. Does not read conversation transcripts.
ellmos-dev-quality
source		 Skills for bug sweeps, bug-fix protocol, merges, Mermaid checks, publish checks, renames, dev cycle. Instructions only: no code, no hooks, no stored data.
ellmos-decision-kit
source		 Skills for structured decisions and decision briefings. Instructions only: no code, no hooks, no stored data.

Privacy policy

  • The plugins run entirely on your computer. They send nothing over the network (the one exception is the optional, opt-in leases of ellmos-lock-master, which go only to a database you run yourself), contain no analytics or telemetry, and we receive no data from them.
  • Data they keep is listed in the table above and stays on your machine; delete it at any time (lock files, ~/.workflowhooker/).
  • The plugins do not read Claude's memory, chat history or conversation summaries and do not build user profiles.
  • Your conversation with Claude is processed by Anthropic under Anthropic's own terms; the plugins add no further processing.
  • No personal data is collected, so there is nothing to share, sell or retain. Questions: see Support.

Support

  • Bugs and questions: GitHub Issues of the plugin's source repository (links in the table).
  • Security reports: privately via GitHub Security Advisories of the repository or security@ellmos.ai.
  • Other contact: support@lukasgeiger.com.

Datenschutzerklärung (Deutsch)

Stand: 31.10.2026. Anbieter: ellmos-ai (Lukas Geiger).

  • Die Plugins laufen vollständig auf deinem Rechner. Sie senden nichts ins Netz (einzige Ausnahme: die optionalen, ausdrücklich einzuschaltenden Leases von ellmos-lock-master, und die gehen nur an eine Datenbank, die du selbst betreibst), enthalten keine Analyse oder Telemetrie, und wir erhalten keine Daten von ihnen.
  • Welche Daten sie lokal lesen oder ablegen, steht in der Tabelle oben; alles bleibt auf deinem Gerät und lässt sich jederzeit löschen (Lock-Dateien, ~/.workflowhooker/).
  • ellmos-lock-master liest LOCK*.txt im Zielordner, in dessen Elternordnern und im Hauptklon eines Worktrees und schreibt Lock-Dateien nur bei /lock und /unlock sowie eine Team-Lock-Nachricht bei /message. Der mitgelieferte MCP-Server lock-board (fünf Werkzeuge: lesen, schreiben, beanspruchen, freigeben, Anwesenheit) schreibt nur dann in die Team-Lock-Datei dieses Rechners, wenn das Modell ihn aufruft; dort stehen Agentennamen, Dateipfade und Nachrichten. Je Sitzung legt der Hook eine kleine JSON-Datei im Temp-Ordner des Systems (ellmos-lock-master) mit dem Sitzungsnamen und den Fence-Nummern der genutzten Locks an; sie wird am Sitzungsende zusammen mit den Board-Ansprüchen der Sitzung entfernt und nach einer Woche aufgeräumt. Optionale Leases (aus, solange ELLMOS_LOCK_LEASES nicht gesetzt ist): Jede Bearbeitung sendet den Lease-Schlüssel der Datei (Repository-Origin und Pfad), Rechnername, Sitzungs-ID und Werkzeugname an die Datenbank, die du selbst einstellst (lokale SQLite-Datei oder eigener Postgres-Server); an ellmos-ai geht nichts. workflowhooker liest Hook-Eingabe, workflowhooker.toml, Projektdateien und git status und speichert je Sitzung Zähler und Hashes sowie (bei ownership = "session", der Starter-Vorgabe) die relativen Pfade der beim Sitzungsstart uncommitteten Dateien mit je einem Inhalts-Hash; Gesprächstranskripte liest es nicht. ellmos-dev-quality und ellmos-decision-kit bestehen nur aus Anleitungen.
  • Die Plugins lesen weder Claudes Gedächtnis noch Chatverläufe oder Gesprächszusammenfassungen und bilden keine Nutzerprofile.
  • Dein Gespräch mit Claude verarbeitet Anthropic nach eigenen Bedingungen; die Plugins fügen keine weitere Verarbeitung hinzu.
